# CLAUDE.md

Трекер тренировок на одного пользователя. PWA для iPhone, использование в зале между подходами.

## Документы - читать перед работой

- `docs/PRD.md` - требования, user stories, продуктовые правила 1-6
- `docs/ADR-001-stack.md` - стек и почему
- `docs/DATA-MODEL.md` - схема данных и механики. Источник истины по базе
- `docs/BACKLOG.md` - слайсы и порядок работы

## Стек (зафиксирован, не менять)

- Vite + React + TypeScript (strict, без any) - SPA
- Supabase: Postgres + Auth (Google) + RLS. Запросы с фронта через supabase-js
- Серверного кода нет. Edge Functions в v1 не используем
- Библиотеки: supabase-js, react-router, TanStack Query (серверное состояние), Tailwind
- Хостинг: Vercel, деплой через git push

## Жёсткие правила

1. **Схема - только через миграции** в `supabase/migrations/`. Никаких правок базы руками или мимо файлов. Одна миграция = одно осмысленное изменение.
2. **RLS на каждой новой таблице** в той же миграции: `user_id = auth.uid()`. Исключение - muscle_groups (глобальный справочник, read-only).
3. **История неприкосновенна**: sets - append-only с точки зрения бизнес-логики; правки шаблонов и упражнений никогда не меняют существующие sets. Упражнения и шаблоны архивируются (is_archived), не удаляются.
4. **Ratchet** (правило 4 PRD): вес в template_exercises двигается автоматикой только вверх, руками - в любую сторону. Для bodyweight то же самое по reps_planned. Не «улучшать» механику без явного запроса.
5. **Инварианты - в базе** (CHECK, unique, FK), не только в коде фронта.
6. **Секреты**: на фронте только anon key; service_role - никогда и нигде, включая скрипты и локальные тулы.
7. **Скоуп**: работаем строго по одному слайсу из BACKLOG.md. Идеи вне слайса - предлагать в парковку, не реализовывать молча.

## UX-принципы

- Mobile-first, вьюпорт 390px. Десктоп - как получится, не приоритет
- Тап-таргеты >= 44px, руки в зале потные
- Отметка подхода: <= 2 тапа, <= 3 секунды. Это главная метрика продукта
- Каждый тап пишется в базу сразу; при ошибке сети - явная ошибка, не тихая потеря
- Никаких модалок там, где хватает inline-контрола

## Команды

- `npm run dev` - локально
- `npm run build && npm run preview` - проверка прод-сборки
- `npx supabase migration new <name>` - новая миграция
- `npx supabase db push` - применить миграции к проекту
- `npm test` - unit-тесты (vitest)
- `npm run check` - `tsc -b && oxlint && vitest run` (гейт перед мержем)

## Git-процесс

- Работа только в ветках: `slice-N-<тема>` для слайсов, `fix/<тема>` для правок. Прямой коммит в `main` - нет.
- Мерж в `main` только после зелёного `npm run check` (руками или через субагента `test-runner`).
- Параллельная работа - через `git worktree`, чтобы две ветки не дрались за один рабочий каталог.

## Definition of Done для слайса

1. Миграции применены, типы обновлены
2. Логика ratchet и вычисления плана покрыты unit-тестами (остальное - руками)
3. После любых изменений кода - `npm run check` зелёный; мерж в `main` только на зелёном
4. Задеплоено на Vercel, проверено с реального айфона
5. Коммит с внятным сообщением, ссылка на слайс

## Стиль работы

- Отвечать по-русски, коротко, без воды
- Сомнения по продуктовой логике - спрашивать, а не угадывать: источник истины - PRD и DATA-MODEL
- Если факт противоречит документам - остановиться и показать конфликт, не чинить молча
- После принятия изменений останавливать дев-сервер - не оставлять `npm run dev` висеть в фоне
