# PRD: Трекер тренировок (v1)

## Проблема

Тренировки трекаются в гугл-доке: вес прошлой недели ищется скроллом, правки с телефона в зале неудобны, разделения план/факт нет. Цена - потерянная прогрессия и лишние минуты между подходами.

## Решение в одну строку

PWA (ставится на главный экран iPhone без стора), данные и Google-auth - Supabase, фронт - Vite + React, хостинг статики - Vercel. Детали и альтернативы - в ADR (этап 2).

## Пользователь

Один - владелец. Мультиюзерность не проектируем, приватность данных обеспечивает RLS by design.

## Ключевые продуктовые правила

1. **Вес живёт на паре «упражнение + день».** Одно упражнение в двух днях - два независимых веса и две независимые истории прогрессии.
2. **Один рабочий вес на упражнение в сессии.** Пирамид нет: план = подходы x повторы x один вес. Точечная коррекция отдельного подхода (вес/повторы) возможна, но это правка факта, на план она не влияет.
3. **Тап = сделал по плану.** Один тап засчитывает подход с плановым весом и повторами. Ввод руками - только при отклонении.
4. **План следует за фактом вверх (ratchet).** Поднял рабочий вес в сессии - план следующей тренировки этого дня обновляется автоматически, перебивать руками не нужно. Снижение веса пишется в историю, но план не трогает; осознанный деволоад - ручной правкой шаблона.
5. **Автосохранение.** Каждый подход уходит в базу сразу после тапа. Закрытая вкладка или севший телефон не теряют тренировку. При потере сети - явная ошибка (пилюля «Нет сети» в интерфейсе), тап не теряется молча (слайс 11); полноценный оффлайн - non-goal.
6. **Архив вместо удаления.** Упражнения и шаблоны архивируются - история выполнений неприкосновенна. Единственное исключение: тренировка, отменённая до 20% плана, удаляется целиком как ошибочный старт - она не появляется в истории (слайс 12).

> Допущение к правилу 4: асимметрию (вверх - автоматом, вниз - руками) я консолидировал из ответов «дефолт по предыдущей тренировке» + «обновлять, если перебил выше». Альтернатива - полная симметрия (план всегда = последняя сессия). Переключение - одна строка в логике, решение не блокирует схему данных.

## User stories

Формат: одна персона, «хочу X, чтобы Y». Приоритеты - MoSCoW.

### Навигация и главный экран

Нижнего меню нет. Закрыто слайсом 14 (29.10.2026).

- [must] Открыть приложение и сразу увидеть «Прогресс» («/» редиректит на /progress) с большой кнопкой «Начать тренировку», прибитой к низу, чтобы старт тренировки был на первом экране без поиска.
- [must] Кнопка старта ведёт в обычный флоу тренировки (/workout): выбор дня, а при активной сессии - возврат в неё.
- [must] Дойти до любого раздела через плавающий кружок профиля в углу: email, ссылки «Тренировка / Дни / История / Справочник упражнений», «Выйти»; панель закрывается тапом мимо, повторным тапом или навигацией.

### Авторизация

- [must] Войти через Google, чтобы данные были привязаны к аккаунту и доступны с любого устройства.
- [must] Сессия живёт месяцами, чтобы не логиниться перед каждой тренировкой.

### Справочник упражнений

- [must] Завести упражнение (название), чтобы использовать его в шаблонах дней. Вес задаётся при добавлении в день (правило 1).
- [must] Архивировать упражнение вместо удаления, чтобы история не потерялась.
- [could] Заметка к упражнению (настройка тренажёра, высота сиденья), чтобы не вспоминать в зале.

### Шаблоны дней

- [must] Создать день (Push / Pull / Legs) и добавить упражнения в нужном порядке, чтобы собирать день один раз.
- [must] Задать план упражнения в дне: подходы x повторы x стартовый вес, чтобы на тренировке видеть цель.
- [must] Использовать одно упражнение в нескольких днях с независимыми весами.
- [must] Править вес в шаблоне руками, чтобы делать осознанный деволоад (правило 4).
- [should] Менять порядок упражнений в дне под реальный маршрут по залу.

### Активная тренировка (ядро продукта)

- [must] Начать тренировку выбором дня и видеть весь план: упражнения, подходы x повторы x вес (вес - из последней сессии этого дня, для первой - стартовый из шаблона).
- [must] Видеть рядом с каждым упражнением результат прошлого раза, чтобы решать про прогрессию на месте.
- [must] Отметить подход одним тапом (= план выполнен), тратя на телефон < 3 секунд.
- [must] Поднять рабочий вес упражнения в сессии - оставшиеся подходы считаются по нему, план следующей тренировки обновляется автоматически (правило 4).
- [must] Точечно поправить вес/повторы отдельного подхода, чтобы история была честной.
- [must] Каждый подход сохраняется сразу (правило 5).
- [must] Завершить тренировку и увидеть короткое резюме: тоннаж, выполнено из плана.
- [should] Пропустить упражнение или подход - занятый тренажёр не блокирует завершение.
- [should] Добавить внеплановый подход или упражнение прямо в сессию.
- [must] Тренировка на экране - одно упражнение (пейджер с точками прогресса и «Назад/Далее»), чтобы не скроллить длинный план между подходами.
- [must] Отменить тренировку, пока выполнено < 20% плана, чтобы ошибочный старт не попал в историю (исключение из правила 6). Позже 20% - только «Завершить».
- [must] Таймер отдыха: автостарт 90с после записанного подхода, отсчёт в липкой панели, «+30с» и «Пропустить». По окончании - звук; панель не сбрасывается при переключении упражнения.

### История

Вход - через плавающий кружок профиля (ссылка «История»); нижнего меню нет, поэтому отдельный таб и не понадобился (слайс 14). Закрыто слайсом 9 (29.10.2026) - вместе с ним закрыт Milestone 2: все must из PRD реализованы, MVP готов.

- [must] Список прошедших тренировок с датами, чтобы контролировать регулярность: только завершённые сессии, новые сверху; строка = день, дата («29 окт», прошлые годы - с годом) и «X/Y из плана»; полный план - mint-пилюля с лапкой. Пустое состояние - с котом.
- [must] Детали прошлой сессии: подходы по упражнениям («№1 60×10», bodyweight - «×12»); плановые упражнения в порядке дня, внеплановые - после с бейджем «вне плана», плановое без подходов - «Подходов нет»; резюме внизу: тоннаж, выполнено из плана.
- [should] По упражнению в дне - последние N результатов списком: строка «Последние: 60×8, 60×8, 60×9» в редакторе дня - до 3 последних завершённых сессий, последний подход каждой, от свежей к старой. График - v2.

### Импорт

- [should] Разовый импорт текущей программы из Google Sheets, чтобы стартовать не с пустого справочника.

### Прогресс

Главный экран приложения (слайс 14: «/» редиректит сюда, снизу прибита кнопка «Начать тренировку»; изначально - слайс 13, когда экран жил в нижнем меню). Всё считается на клиенте из существующих таблиц, без миграций. Спеки: PROGRESS.md (исследование и формулы), PROGRESS-UX.md (UX).

- [must] Экран «Прогресс» с живыми цифрами по реальным тренировкам, чтобы был ответ на вопрос «зачем идти в зал сегодня»: герой «+дни жизни» (игривая экстраполяция Momma 2022 с дисклеймером и раскрышкой формулы), тоннаж и время в зале, тренировки и стрик.
- [should] Бары тоннажа по 8 неделям и разбивка по группам мышц (основная группа, top-5 + «Прочее»), чтобы видеть, что зал «работает».
- [should] Рекорды: самый тяжёлый день, лучший стрик, максимум веса по упражнениям.
- [must] Честная карточка «Про Паркинсон» без выдуманных процентов: про силовую наука пока не отвечает, ассоциация по активности - на популяции, не прогноз.
- [must] Дисклеймеры у игровых цифр: «+дни жизни» и бары - мотивация, не медицина и не аналитика; кап 4 ч на сессию в тоннаже подписан.

## Критерии успеха

- Отметка подхода: <= 2 тапа и <= 3 секунды.
- Через 2 недели использования гугл-док не открыт ни разу.
- Ручной ввод веса случается только при смене планки или отклонении от плана.

## Non-goals v1

Графики прогресса, пуши, шаринг, мультиюзерные фичи, полноценный оффлайн, LLM-аналитика. Парковка для v2 - ничего из этого не влияет на ценность первой тренировки. (Таймер отдыха и фокус-режим добавлены слайсом 12 по запросу пользователя - из non-goals исключены.) Уточнение по слайсу 13: бары тоннажа по 8 неделям на экране «Прогресс» включены как мотивационная картинка - 8 столбиков без осей, тапов и тултипов (О6 в PROGRESS-UX.md), а не «графики прогресса»-анализ, который остаётся non-goal.

## Открытые вопросы

- UX смены рабочего веса в сессии (степпер +2.5 кг vs ввод с клавиатуры) - решается на этапе 5, схему данных не блокирует.
